- Corre `build.py --check`, genera HTML, ejecuta 11 tests existentes por versión, revisa JavaScript con `node --check` y ensaya recuperación.
- [`scripts/qa_guardrails.py`](../scripts/qa_guardrails.py): clona localmente a una carpeta temporal, altera un byte del dataset, exige que el build falle, restaura los bytes, simula un commit accidental sobre README y ejecuta `git revert`; prueba la equivalencia final y HEAD original intacto.
- [Runbook de recuperación](RECOVERY.md) con pasos para corregir un commit en una rama, sin `push --force`, sin tocar producción.
- Migración de `actions/checkout` y `actions/setup-python` a `@v6` para evitar advertencias de Node 20 observadas en la primera ejecución.

## Control de acceso y riesgos

- GitHub Actions tiene permisos **solo lectura** y no incluye ninguna instrucción de despliegue. No añade secretos ni cambia Vercel.
- La conexión GitHub no pudo leer el endpoint de protección de ramas (403), y el listado de rulesets no mostró reglas existentes. Por tanto, **no se afirma que los checks sean obligatorios para fusionar**.
- Las pruebas en el clon temporal ensayan el procedimiento de rollback, pero nunca modifican `main` ni realizan pushes.
